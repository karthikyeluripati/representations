### Environment and branching
- ALFWorld 0.4.2 with TextWorld 1.7.0. After ALFWorld's own filters there are 3553 train, 140 valid_seen and
  134 valid_unseen games.
- `PddlEnv.copy()` raises `NotImplementedError`, so **branching uses deterministic replay**.
- `scripts/check_environment.py` passed on 5 games, both on WSL and on the pod. A 30-step random walk replayed
  in a fresh env matched at every step on the full PDDL fact-set hash, the observation text and the admissible
  set. Re-branching from the midpoint was reproducible, and different actions led to different states.
  Cost: reset about 0.6 s and step about 0.08 s (laptop).
- **Finding: ALFWorld's PDDL state has history-bookkeeping predicates.** `checked(x)` is added by
  look, examine and inventory, and `not_atlocation(agent, loc)` accumulates every location left. They are
  monotone, so the full-fact hash never repeats within an episode. The first wasted-action measure used that
  hash and undercounted badly: random policy waste was 0.11, and `look` was flagged wasted in only 6 of 42 uses.
  Fix: a separate *world* fingerprint that excludes these two predicates, used only for waste.
  The strict hash is still used to verify state restoration. A regression test covers it.

**Observation (zero-shot).** Greedy likelihood scoring degenerates into repetition loops, for example
"examine bowl 1" 43 of 50 times. With λ=1, the cosine bonus does not break the loops; it only perturbs a few
choices. Bonus scales were **not tuned**, so this says nothing yet about novelty bonuses in general.
The practical consequence is that a zero-shot frozen 3B policy is too weak to serve as a branch-rollout policy:
nearly every branch would have success ≈ 0, which makes value labels uninformative.

**Change (documented, deliberate).** We added one expert demonstration per task family, generated by
ALFWorld's handcoded expert on **train** games (`src/dare/agents/demos.py`, sources in
`results/demos/demos_v1.json.sources.json`). Those 6 train tasks are excluded from decision datasets.
This mirrors ReAct's task-type-specific prompts.

**Few-shot prompt** (`configs/baseline_pod.yaml`), same 12 games, output of `scripts/summarize_runs.py`:

| policy | success | 95% CI | env actions / success | LM tokens / success | wasted rate | LM+select s / step |
|---|---|---|---|---|---|---|
| random | 0/12 | 0.00–0.24 | ∞ | ∞ | 0.41 | 0 |
| frozen_lm | 2/12 | 0.05–0.45 | 280 | 424,708 | 0.76 | 0.28 |
| cosine_novelty | 3/12 | 0.09–0.53 | 165 | 251,248 | 0.73 | 0.33 |
| elliptical_novelty | 3/12 | 0.09–0.53 | 174 | 260,755 | 0.71 | 0.68 |

**Interpretation.**
- Demonstrations help a little (frozen 1/12 → 2/12, waste 0.83 → 0.76), but the policy is still weak.
- The novelty arms reach 3/12 versus 2/12. That difference is **one episode at n=12**, and the CIs overlap almost
  entirely, so it is **not evidence** of an effect.
- The elliptical bonus doubles per-step selection cost (an H×H inverse with H=2048, in numpy on the CPU).
  A random projection to d≈512, as in RepExp, would cut this and must be counted in matched-compute comparisons.

## 2026-11-17: Session 1, continued (GPU optimisation, 7B arm)

### Throughput and memory work (A40)
- The first 5-shard launch reached 100% utilisation but crashed with CUDA OOM (10–12.6 GB per process).
  Cause: each 64-candidate chunk copies the ~1.5k-token prompt KV cache, which GQA then expands 8×.
- Fixes:
  - `max_batch` 16;
  - **static-prefix KV reuse**: system prompt, demo and task intro are computed once, always from scratch;
  - a per-process allocator cap (`DARE_CUDA_MEM_FRACTION`);
  - a crash-restart watchdog (`scripts/run_shards.sh`; resumable rows).
- Result on one process: prompt tokens computed dropped from 211k to 80k (−62%), per-step time from 0.264 to
  0.219 s, and peak memory from 10–12.6 GB to 8.2 GB.
  With 5 shards: about 94–100% utilisation and 42–43 GB of 44.4 GB.
- **Finding: the greedy bf16 policy is numerically fragile.**
  - The first, naive version of prefix reuse (longest common prefix against the *previous* call) changed greedy
    decisions, giving 0/4 vs 2/4 successes on identical games.
  - That version made scores depend on call history, which is unacceptable for branching.
  - The final design makes the split point a function of the prompt alone. History-independence is
    bitwise-tested in bf16 (3B, GPU).
  - `max_batch`, `device` and `reuse_prefix` all change bf16 numerics, so all of them stay in the config hash.
  - Implication: small-n policy comparisons are even noisier than their CIs suggest.
- Measured throughput of the 3B 60-task collection: about 1.4 rows/min with 5 shards, so roughly 8–9 h for 720
  rows. Failing rollouts run to the 50-step cap, which dominates the cost.

### Phases B–D: protocol (`scripts/probe_decisions.py`)
- **Commands:**
  - `python scripts/probe_decisions.py --decisions results/decisions_v1_{3b,7b} --out results/phase3/probes_{3b,7b}.json --n-perm 50 [--action-text-emb results/phase3/action_text_emb_7b.npz]`
  - 3B action-only run: `--models act_text --action-text-emb results/phase3/action_text_emb_3b.npz`
  - Diagnostics: `python results/phase3/diagnostics.py results/decisions_v1_{3b,7b} results/phase3/diagnostics_{3b,7b}.json`
  - Tables: `python results/phase3/summarize_probes.py results/phase3/probes_{3b,7b}.json`
- **Objective:**
  - within-state pairwise logistic loss on pairs with unequal success;
  - pair weight |Δp|, normalized to total weight 1 per **state**, so pairs are not treated as independent;
  - target = success rate. Remaining-steps ranking is evaluated with the same scores.
- **Predictors:**
  1. LM mean log-prob, no fitted parameters (sum log-prob also reported);
  2. `linear`: PCA (k ∈ {16, 64}) of the contextual action embedding + L2 pairwise logistic
     (C ∈ {0.01, 0.1, 1});
  3. `mlp`: PCA-64 → 64 hidden → 1, dropout 0.2, weight decay ∈ {1e-3, 1e-2, 1e-1}, 300 epochs,
     5-seed ensemble;
  4. `mlp_ctx`: MLP on [action PCA-32, context PCA-32];
  5. `proj`: learned low-rank state-action interaction s = w·a + ⟨P a, Q c⟩, r = 8;
  6. `verb`: one-hot action-type prior;
  7. `act_text`: linear probe on context-free action embeddings;
  8. state-only: constant within a state, so it is tested as a state-value regressor instead.
- **Fitting rules:**
  - PCA, standardization and z-scaling are fit on training rows only;
  - hyperparameters chosen by 4-fold task-grouped CV inside the training tasks;
  - backbone frozen.
- **Evaluation:**
  - **fit_nestedcv**: outer 5-fold task-grouped CV over `fit`, with inner selection;
  - final model trained on all `fit` and scored on `dev` and `family_holdout` (evaluated once);
  - **combined score**: z(logp) + α·z(probe), α ∈ {0, .25, .5, 1, 2, 4} tuned on dev only, then applied
    to holdout and to fit-OOF.
- **Metrics:**
  - pooled within-state pairwise accuracy;
  - the **paired** difference from logp on the same pairs, with a task-cluster bootstrap (2000 resamples);
  - a subset of pairs with Δp ≥ 2/8;
  - disagreement analysis;
  - a 50-permutation within-state label-shuffle null for the linear probe.

### Phase E: decision. **PIVOT** (for the action-ranking question at this data scale)
- **GO criteria not met.** No predictor shows a reliable positive paired improvement over LM logp on
  held-out tasks:
  - every fit-CV paired Δ ≤ +0.02, and several are significantly negative;
  - holdout Δ is negative (3B) or ≈ 0 with ±0.15 CIs (7B);
  - the one positive combined result does not replicate.
- **Not CONDITIONAL GO.** Dev results are not promising either.
- **The diagnostics identify the limitation:**
  1. Training signal for within-state action contrasts is tiny and noisy: 67–81 informative training
     states, most pairs separated by 1/8 rollouts. Even logp is near chance on large-gap holdout pairs
     (0.47–0.48).
  2. Probes fit training tasks, but learning curves rise only slowly and stay below logp.
  3. Action-only, action-type, state-action and learned-projection variants all fail the same way, so
     this is not one representation choice.
  4. State-level value **is** linearly decodable from frozen states and transfers to held-out families.
- **Implication:**
  - At ~60 tasks × 3 states × 4 candidates × 8 rollouts, frozen embeddings add no action-ranking
    information beyond the policy's own preference.
  - This does **not** show the information is absent. The data cannot resolve effects smaller than
    roughly ±0.05–0.10.
- **Pivot options**, for a decision before any new spend:
  - (a) State-value / progress representations as an exploration signal (the positive finding). For
    example, a bonus for visiting states whose decoded value is uncertain or high, compared with novelty.
  - (b) A better-powered action-contrast dataset:
    - spend rollouts only on informative states (adaptive: stop all-0 states after a few rollouts);
    - ≥200 tasks, 16–32 rollouts per candidate on informative states;
    - a fresh held-out set from `valid_unseen`.
  - No RL was trained.

## Pivot: state-value representation feasibility (2026-11-18)

Question: do frozen LM state representations give a transferable estimate of future success that beats
simple deployable baselines? Action-ranking hypothesis suspended.
Code: `scripts/state_value.py`. Summaries: `results/phase3/summarize_sv.py`.

### Stage 1: target and shortcut audit
- **Target ("state promise")**, `v_mean(s)`:
  - the mean over the 4 sampled candidates (the policy's choice plus 3 random others) of p̂(success | s, a);
  - each p̂ is 8 rollouts: take a, then follow the frozen LM policy (T=0.5) until won or the
    **50-step horizon, counted from episode reset**;
  - so 32 rollouts per state.
  - It is **success before a fixed horizon**: no efficiency term, no remaining-steps mixture.
  - Verified: every all-fail row has step + remaining = 50, and max(step + remaining) = 50.
  - Future information enters only the label. Secondary target: `v_choice` = p̂ for the greedy choice.
  - Label noise floor (binomial MSE): 3B 0.0019, 7B 0.0028.
- **Progress shortcut is built into the target.** Value at step ≥ 40 is 0.016 (3B) / 0.022 (7B), and
  16% / 12% of states are there.
  - Remaining budget is a legitimate deployable feature: the agent knows its step count.
  - Every metric is therefore also reported on step < 40 and within 10-step bins (matched-step pairwise
    ranking).
- **Deployable features:**
  - step, step²;
  - task family parsed from the objective template (100% accurate, no task id used);
  - number of admissible actions;
  - LM policy entropy, top-1 margin and max mean-logp over all admissible actions (logged at every step);
  - history-derived progress proxies: holding an object, fraction of objective words seen,
    invalid-action rate, repeated-observation rate.
- **Protocols** (development, held-out family untouched):
  - `cv_task`: nested 5-fold task-grouped CV on `fit` (120 states, 40 tasks);
  - `lofo`: leave-one-family-out over the 5 development families (150 states).
  - Hyperparameters: inner 4-fold task-grouped CV, minimizing MSE.
  - The strongest non-embedding baseline was picked by cv_task MSE: 3B = step-only, 7B = observable.
  - **Final test, run once**: train on fit + dev, test on `pick_two_obj_and_place` (30 states).
  - CIs: task-cluster bootstrap, 2000 resamples, paired on the same states.
- **Commands:**
  - `python scripts/state_value.py --decisions results/decisions_v1_{3b,7b} --out results/phase3/state_value_{3b,7b}_dev.json`
  - then the same with `--final-test` → `state_value_*_final.json`.

### Stage 3 / 4: not run (gate not met)
- Stage 3 needs next-state embeddings for each candidate. They are not stored. They would need ALFWorld
  replay (prefix + action per candidate) plus one LM forward each on a GPU.
- It was gated on Stage 2 showing embedding information beyond observable baselines. That holds only
  for 3B development and does not survive the 3B test or replicate on 7B.
- **Cost of an online value-lookahead intervention** (from source logs):
  - mean step 23–24, 31 admissible actions (median 27);
  - baseline per step: ~435–478 computed prompt tokens, 0.3–0.5 s of LM and 0.07 s of environment time
    on H100.
  - Scoring m candidates' next states adds m environment executions, each needing a prefix replay in
    ALFWorld (~25 env steps, since state cannot be copied), plus m LM forwards.
  - m = 4: ~100 env steps (~7 s) and ~4× LM compute per decision. All candidates: ~775 env steps and ~25×.
  - In a non-simulator environment these lookahead actions are irreversible, so not available at all.

### Stage 5: literature and novelty
- Directly overlapping 2026 work:
  - **POISE** ("Your Language Model is Its Own Critic", arXiv 2605.07579): linear and other probes on the
    policy's own hidden states as the value model;
  - **Conformal interpretability of temporal concepts in LLM agents** (arXiv 2604.19775): linear probes on
    residual-stream states separate on-track from failing steps in ALFWorld, with MC-rollout labels;
  - **"Doomed from the Start"** (arXiv 2607.06503): hidden-state probes predict episode failure and
    abort early.
- Value / state-score-guided exploration and credit assignment on ALFWorld:
  - 3SPO (2606.09961): state scores from historical success rates, adaptive rollout;
  - BEACON (2605.06078): milestone-segmented advantages;
  - QLASS: Q-guided search;
  - LATS: value-guided tree search;
  - LINVIT / SLINVIT: LLM prior + value.
- "State value is decodable from frozen LM representations" is already published, and our data says
  observable features (step, policy entropy, family) match or beat it at this scale.

### Stage 6: decision. **PIVOT away from representation-derived state value; STOP the claim as a contribution.**
- **Claim 1** (decodable): yes, ρ 0.44–0.67 with embedding alone. Mostly shared with step count and
  policy confidence.
- **Claim 2** (beyond shortcuts, transfers):
  - not established;
  - 7B: embeddings add nothing over observable features (development Δρ −0.02 to −0.05, test +0.01);
  - 3B: a development gain (lofo +0.14) that does not survive the held-out test (+0.01 [−0.21, 0.16]);
  - the test has only 30 states and 10 tasks.
- **Claim 3** (improves decisions): not tested, because the gate failed. The action-ranking results
  already showed frozen embeddings don't beat logp for choosing actions.
- **GO gates failed:** reliable information beyond observable baselines, and a defensible contribution
  given POISE, the conformal-probe paper and "Doomed from the Start".
- **Limitations:**
  - 180 states per model, 30 test states, MC labels from 32 rollouts;
  - one environment, one embedding layer (last) and one pooling position;
  - the observable baseline was designed after seeing data structure, though not test results.
- **No new compute was used.** All analysis ran locally on CPU.

- No method gap.
- The one empirical gap was tested and came out negative or uninformative:

### Stage 1: code inspection (RepExp `rep_exp/workers/elliptical_reward_model_worker.py`, `train_elliptical.sh`)
1. **Features:** frozen `Qwen2.5-7B-Instruct` `AutoModel.last_hidden_state` (after the final norm), averaged
   over response tokens, from a prompt + response forward.
2. **Bonus:**
   - sparse random projection to `sparse_dim`, redrawn each call;
   - float64, centered within the `uid` group;
   - Σ = λI + Σ hhᵀ with λ = 0.01, using rank-1 updates over all group members;
   - leverage bonus hᵀΣ⁻¹h;
   - `normalization=none`; reward = task reward + β·bonus (β = 0.01);
   - the bonus is zeroed when no rollout is correct.
3. **Unit:** the whole response, compared within the group of `rollout.n=8` rollouts for one prompt.
   `persist_covariance=False`.
4. **Applies to tool-use responses:** yes, the formula is defined over any response.
   - **Caveat:** every rollout in a group shares one schema, so cross-prompt schema renaming can't affect a
     faithful bonus.
   - Only within-schema surface variation (aliases, key order, call order, prose) or persistent memories
     can.
5. **TSS operators:** each is proven lossless by decoding to native actions (`tests/`). The single-call
   operators keep one call per action. Transaction, reference and discovery add calls and are excluded here.

- **Mechanism (7B):**
  - The faithful bonus is effectively constant over non-identical responses: mean 0.856, within-group
    coefficient of variation 0.16% over 7 distinct behaviors.
  - The bonus of a surface duplicate divided by the bonus of a new behavior is **1.00 [1.00, 1.00]** for every
    surface family; it is 0.43 for exact copies.

  - With n = 8 < 32 projected dims, the centered group is almost linearly independent, so every non-identical
    response gets leverage ≈ (n−1)/n.
  - **In its published configuration, RepExp's within-group bonus detects exact copies.** It doesn't grade

### Stage 5: Gate E, learned invariant representation: FAIL (not trained)
- Canonical-action novelty is the decoded native call sequence. It needs only the schema decoder the tool
  runtime already has, with no execution and no GPU.
- It reaches 2.97 / 2.57 unique states, against the oracle's 3.00 / 2.65. A learned TIE representation can
  improve at most 0.03–0.08 unique states (canonical vs state).
- The residual case is call-order permutation of commutative calls, and order-insensitive canonicalization
  (the state multiset) already fixes it.
- TIE would also be post-transition only, like state novelty.
- **No case was found where simple canonicalization fails, so training was not justified and not run.**
- Learned invariance could matter only where no decoder or canonical state exists (free-form observations:
  web, GUI). This benchmark can't test that; that is a different project.
